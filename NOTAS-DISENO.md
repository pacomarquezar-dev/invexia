# Notas de diseño

- Calculadora FIRE: el dato de "años para alcanzarlo" debería tener más protagonismo visual que el "número FIRE" en sí — es el resultado más impactante para el usuario y actualmente pasa desapercibido.
- Revisar el nombre "número FIRE" — es una jerga poco conocida y poco atractiva para el público objetivo (gente joven que empieza en finanzas). Buscar un nombre más descriptivo relacionado con jubilación/independencia financiera antes del lanzamiento.
- Los gráficos de las calculadoras funcionan bien mecánicamente pero visualmente son poco atractivos — pendiente de mejorar en la fase de diseño con referencias.
- Pantalla de resultado del test de perfil: darle identidad visual propia por perfil (color/icono distinto para Conservador/Moderado/Agresivo) y personalizar el texto según respuestas concretas, no solo la categoría general. Explorar una versión "tarjeta para compartir" pensada para redes sociales, al estilo de un resultado de test de personalidad. Sin estadísticas comparativas entre usuarios (no hay base de datos).
- El rate limiting del chatbot (20 mensajes/24h) es en memoria, por instancia del servidor — no un límite global exacto si Vercel escala a varias instancias. Suficiente para tráfico bajo actual. Si el tráfico crece, migrar a un límite distribuido real (ej. Vercel KV / Upstash Redis) para que el límite sea exacto entre instancias.
- El botón/icono del widget de chat es poco visible y no comunica bien que es un chatbot — parece más un botón de "leer" o "dejar opinión". Cambiar en la fase de diseño por un icono y estilo que se reconozca claramente como chat/asistente (ej. icono de burbuja de conversación, color que destaque, quizá con una etiqueta de texto tipo "¿Dudas?" o similar).
- Chatbot: al recibir una respuesta, el chat hace scroll automático hasta el final absoluto, mostrando el final de la respuesta en vez de su principio — obliga a subir manualmente para leerla desde el inicio. Comportamiento correcto a implementar: al llegar una respuesta nueva, el scroll debe situarse justo al principio de esa respuesta (no al final del todo), y solo seguir el scroll automáticamente hacia abajo si el usuario ya estaba al final de la conversación (no interrumpir si el usuario había subido a leer algo anterior).
